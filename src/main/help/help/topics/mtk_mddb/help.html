MediaTek MDDB

The MediaTek MDDB plugin opens Catcher/META .EDB modem databases that use the CATD container, decodes their raw-LZMA DATAI/DATAA sections, and opens the RocksDB embedded in DATAI.

Browse and decode

  1. Select Tools > MediaTek MDDB > Open EDB....
  2. Search all column families, or restrict the query to one family such as sp, trace, type, struct, or enum.
  3. The Schema column decodes known packed string references and standard enum members, type-alias chains, and common struct/union field descriptors. For example, the tested MT6880 database resolves URF_TEST_CMD_TRIGGER_IQ_DUMP_MODE_V3 to urf_test_cmd_type = 0x58.

Map database names into code

  • Find in Program searches the current program for the same byte string.
  • Go to Code Xref follows Ghidra references from the string into code and navigates to the first code reference.
  • Annotate Program adds analysis bookmarks and comments to string matches and code xrefs, plus an analysis label for identifier-like string names.

The plugin does not claim that an MDDB entry is a code symbol. Production MediaTek modem images often omit md1_dbginfo; MDDB is Catcher/META schema and trace metadata. Program annotations are therefore explicitly marked as MDDB-derived analysis.

The common packed string reference decoded by this plugin uses a 14-bit sp bucket and an 18-bit byte offset. The standard enum layout handled by the schema browser consists of a 23-byte header followed by value/string-reference pairs. Type aliases are followed through the type column family into tagged struct/union records when the known layout is present; field offsets, types, names, and validated one-dimensional array counts are then displayed in the Schema column. On the tested MT6880 database this exposes the IQ result PDU as 8192 elements of a four-byte signed-I/Q pair. Generation-specific structures that do not match validated layouts are deliberately left raw rather than guessed.
